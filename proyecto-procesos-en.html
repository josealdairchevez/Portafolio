Corporate Data Warehouse:
Medallion Architecture

Design and construction of an end-to-end data pipeline. From Data Governance implementation and naming conventions, to flat file ingestion (CRM/ERP), intensive T-SQL cleansing, and Dimensional Modeling.

SQL Server T-SQL Data Governance Medallion Architecture Star Schema ETL Pipelines

Data Governance & Naming Conventions

A robust Data Warehouse requires rigorous standards. Strict Naming Conventions were implemented using snake_case to ensure consistency across all logical schemas and facilitate data lineage tracking between source systems (CRM/ERP) and analytical tables.

  • Raw Tables Standardization (Bronze & Silver)Entities retain their source system name to ensure traceability. Pattern: <sourcesystem>_<entity> (e.g., crm_customer_info).
  • Business Modeling (Gold)Final tables use descriptive names aligned with the business domain, utilizing prefixes dim_ for Dimensions and fact_ for Facts.
  • Technical Metadata & AuditingEvery column auto-generated by the system for audit purposes starts with the prefix dwh_ (e.g., dwh_create_date). Every surrogate key uses the suffix _key.

Architecture Design & ETL Methodology

Integrating concepts from Kimball and Data Lakehouses, a logical Medallion Architecture was designed in SQL Server. This approach guarantees Separation of Concerns (SoC) between raw ingestion, transformation, and data consumption.

Data Layer Objective and Object Type Applied Transformations Load Method
Bronze Layer Traceability. Physical tables (Raw Tables). Data stored "As-Is". None (As-Is). Full Load (Truncate & Insert).
Silver Layer Cleansing and preparation. Physical tables (Cleaned Tables). Data Cleansing, Normalization, Standardization, and Derived Columns. Full Load (Truncate & Insert).
Gold Layer Business consumption (BI & Analytics). Analytical Views. Data Integration, Aggregations, Business Logic, and Data Modeling (Star Schema). None (Real-time Views).

Phase 0: Environment Setup

Every robust Data Warehouse requires a solid foundation. Prior to any ingestion, an initial configuration script (Idempotent) was implemented to safely reset the database (forcing active connections to close) and create the three logical schemas that form the Medallion Architecture.

    DROP DATABASE DataWarehouse;
END;
GO

GO

2. Automated Ingestion Engine

A centralized massive ingestion engine was developed for all sources (CRM and ERP). It implements a BULK INSERT method under the Full Load standard. An Idempotent secure reset pattern (TRUNCATE before insert), execution time auditing, and error handling via TRY...CATCH were applied.

proc_load_bronze.sql (Full Ingestion Engine) 
/*
===============================================================================
Stored Procedure: Load Bronze Layer (Source -> Bronze)
===============================================================================
Purpose:
    Loads data into the 'bronze' schema from external CSV files.
    - Truncates tables before loading (Idempotency).
    - Uses `BULK INSERT` for optimized massive ingestion.
===============================================================================
*/

BEGIN
    -- Variable declaration for performance auditing
    DECLARE @start_time DATETIME, @end_time DATETIME, @batch_start_time DATETIME, @batch_end_time DATETIME;

        SET @batch_start_time = GETDATE();
        PRINT '================================================';
        PRINT 'Loading Bronze Layer';
        PRINT '================================================';

        -- ------------------------------------------------
        -- 1. Loading CRM Tables
        -- ------------------------------------------------
        PRINT '------------------------------------------------';
        PRINT 'Loading CRM Tables';
        PRINT '------------------------------------------------';

        SET @start_time = GETDATE();
        PRINT '>> Truncating Table: bronze.crm_cust_info';
        TRUNCATE TABLE bronze.crm_cust_info; -- Table cleanup to avoid duplicates on restarts

        FROM 'C:\SQL_Datasets\datasets\source_crm\cust_info.csv'

            FIRSTROW = 2,
            FIELDTERMINATOR = ',',

        PRINT '>> Load Duration: ' + CAST(DATEDIFF(second, @start_time, @end_time) AS NVARCHAR) + ' seconds';

2. ETL Automation & Transformation (Master Stored Procedure)

Data cleansing was orchestrated using a sophisticated Master Stored Procedure (silver.load_silver). This engine extracts the raw data, applies business rules using CASE WHEN, cleans text with TRIM, recalculates missing metrics, unifies date formats, and normalizes histories using analytical functions like ROW_NUMBER() and LEAD().

proc_load_silver.sql (Full Transformation Engine) 
/*
===============================================================================
Stored Procedure: Load Silver Layer (Bronze -> Silver)
===============================================================================
Purpose:
    Executes the ETL process to transform and load data from 'bronze' 
    to 'silver'. Applies deep cleansing, normalization, and derived calculations.
===============================================================================
*/
CREATE OR ALTER PROCEDURE silver.load_silver AS
BEGIN
    DECLARE @start_time DATETIME, @end_time DATETIME, @batch_start_time DATETIME, @batch_end_time DATETIME; 
    BEGIN TRY
        SET @batch_start_time = GETDATE();
        PRINT '================================================';
        PRINT 'Loading Silver Layer';
        PRINT '================================================';

        -- ------------------------------------------------
        -- 1. Transforming CRM Tables
        -- ------------------------------------------------
        
        -- Loading crm_cust_info (Duplicate elimination and string cleansing)
        SET @start_time = GETDATE();
        PRINT '>> Truncating Table: silver.crm_cust_info';
        TRUNCATE TABLE silver.crm_cust_info;
        PRINT '>> Inserting Data Into: silver.crm_cust_info';
        INSERT INTO silver.crm_cust_info (cst_id, cst_key, cst_firstname, cst_lastname, cst_marital_status, cst_gndr, cst_create_date)
        SELECT
            cst_id,
            cst_key,
            TRIM(cst_firstname) AS cst_firstname,
            TRIM(cst_lastname) AS cst_lastname,
            CASE 
                WHEN UPPER(TRIM(cst_marital_status)) = 'S' THEN 'Single'
                WHEN UPPER(TRIM(cst_marital_status)) = 'M' THEN 'Married'
                ELSE 'n/a'
            END AS cst_marital_status, -- Marital Status dictionary normalization
            CASE 
                WHEN UPPER(TRIM(cst_gndr)) = 'F' THEN 'Female'
                WHEN UPPER(TRIM(cst_gndr)) = 'M' THEN 'Male'
                ELSE 'n/a'
            END AS cst_gndr, -- Gender dictionary normalization
            cst_create_date
        FROM (
            -- Selection of the most recent record in case of duplicate IDs (Deduplication)
            SELECT
                *,
                ROW_NUMBER() OVER (PARTITION BY cst_id ORDER BY cst_create_date DESC) AS flag_last
            FROM bronze.crm_cust_info
            WHERE cst_id IS NOT NULL
        ) t
        WHERE flag_last = 1;
        SET @end_time = GETDATE();
        PRINT '>> Load Duration: ' + CAST(DATEDIFF(SECOND, @start_time, @end_time) AS NVARCHAR) + ' seconds';

        -- Loading crm_prd_info (String split and SCD)
        SET @start_time = GETDATE();
        PRINT '>> Truncating Table: silver.crm_prd_info';
        TRUNCATE TABLE silver.crm_prd_info;
        PRINT '>> Inserting Data Into: silver.crm_prd_info';
        INSERT INTO silver.crm_prd_info (prd_id, cat_id, prd_key, prd_nm, prd_cost, prd_line, prd_start_dt, prd_end_dt)
        SELECT
            prd_id,
            REPLACE(SUBSTRING(prd_key, 1, 5), '-', '_') AS cat_id, -- Category extraction
            SUBSTRING(prd_key, 7, LEN(prd_key)) AS prd_key,        -- Pure Product Key extraction
            prd_nm,
            ISNULL(prd_cost, 0) AS prd_cost,
            CASE 
                WHEN UPPER(TRIM(prd_line)) = 'M' THEN 'Mountain'
                WHEN UPPER(TRIM(prd_line)) = 'R' THEN 'Road'
                WHEN UPPER(TRIM(prd_line)) = 'S' THEN 'Other Sales'
                WHEN UPPER(TRIM(prd_line)) = 'T' THEN 'Touring'
                ELSE 'n/a'
            END AS prd_line, 
            CAST(prd_start_dt AS DATE) AS prd_start_dt,
            CAST(
                LEAD(prd_start_dt) OVER (PARTITION BY prd_key ORDER BY prd_start_dt) - 1 
                AS DATE
            ) AS prd_end_dt -- Automatic End Date Calculation (SCD Type 2)
        FROM bronze.crm_prd_info;
        SET @end_time = GETDATE();
        PRINT '>> Load Duration: ' + CAST(DATEDIFF(SECOND, @start_time, @end_time) AS NVARCHAR) + ' seconds';

        -- Loading crm_sales_details (Mathematical and Date Validation)
        SET @start_time = GETDATE();
        PRINT '>> Truncating Table: silver.crm_sales_details';
        TRUNCATE TABLE silver.crm_sales_details;
        PRINT '>> Inserting Data Into: silver.crm_sales_details';
        INSERT INTO silver.crm_sales_details (sls_ord_num, sls_prd_key, sls_cust_id, sls_order_dt, sls_ship_dt, sls_due_dt, sls_sales, sls_quantity, sls_price)
        SELECT DISTINCT
            sls_ord_num,
            sls_prd_key,
            sls_cust_id,
            CASE 
                WHEN sls_order_dt = 0 OR LEN(sls_order_dt) != 8 THEN NULL
                ELSE CAST(CAST(sls_order_dt AS VARCHAR) AS DATE) -- INT to DATE Casting (YYYYMMDD)
            END AS sls_order_dt,
            CASE 
                WHEN sls_ship_dt = 0 OR LEN(sls_ship_dt) != 8 THEN NULL
                ELSE CAST(CAST(sls_ship_dt AS VARCHAR) AS DATE)
            END AS sls_ship_dt,
            CASE 
                WHEN sls_due_dt = 0 OR LEN(sls_due_dt) != 8 THEN NULL
                ELSE CAST(CAST(sls_due_dt AS VARCHAR) AS DATE)
            END AS sls_due_dt,
            CASE 
                WHEN sls_sales IS NULL OR sls_sales <= 0 OR sls_sales != sls_quantity * ABS(sls_price) 
                    THEN sls_quantity * ABS(sls_price) -- Recalculate sales if source is corrupt
                ELSE sls_sales
            END AS sls_sales, 
            sls_quantity,
            CASE 
                WHEN sls_price IS NULL OR sls_price <= 0 
                    THEN sls_sales / NULLIF(sls_quantity, 0) -- Derive price / Avoid division by zero
                ELSE sls_price  
            END AS sls_price
        FROM bronze.crm_sales_details;
        SET @end_time = GETDATE();
        PRINT '>> Load Duration: ' + CAST(DATEDIFF(SECOND, @start_time, @end_time) AS NVARCHAR) + ' seconds';

        -- ------------------------------------------------
        -- 2. Transforming ERP Tables
        -- ------------------------------------------------
        
        -- Loading erp_cust_az12 (ID Cleansing and Future Date Control)
        SET @start_time = GETDATE();
        PRINT '>> Truncating Table: silver.erp_cust_az12';
        TRUNCATE TABLE silver.erp_cust_az12;
        PRINT '>> Inserting Data Into: silver.erp_cust_az12';
        INSERT INTO silver.erp_cust_az12 (cid, bdate, gen)
        SELECT
            CASE
                WHEN cid LIKE 'NAS%' THEN SUBSTRING(cid, 4, LEN(cid)) -- Erroneous ERP prefix cleansing
                ELSE cid
            END AS cid, 
            CASE
                WHEN bdate > GETDATE() THEN NULL -- Converts unreal future birthdates to NULL
                ELSE bdate
            END AS bdate, 
            CASE
                WHEN UPPER(TRIM(gen)) IN ('F', 'FEMALE') THEN 'Female'
                WHEN UPPER(TRIM(gen)) IN ('M', 'MALE') THEN 'Male'
                ELSE 'n/a'
            END AS gen 
        FROM bronze.erp_cust_az12;
        SET @end_time = GETDATE();
        PRINT '>> Load Duration: ' + CAST(DATEDIFF(SECOND, @start_time, @end_time) AS NVARCHAR) + ' seconds';

        -- Loading erp_loc_a101
        SET @start_time = GETDATE();
        PRINT '>> Truncating Table: silver.erp_loc_a101';
        TRUNCATE TABLE silver.erp_loc_a101;
        PRINT '>> Inserting Data Into: silver.erp_loc_a101';
        INSERT INTO silver.erp_loc_a101 (cid, cntry)
        SELECT
            REPLACE(cid, '-', '') AS cid, 
            CASE
                WHEN TRIM(cntry) = 'DE' THEN 'Germany'
                WHEN TRIM(cntry) IN ('US', 'USA') THEN 'United States'
                WHEN TRIM(cntry) = '' OR cntry IS NULL THEN 'n/a'
                ELSE TRIM(cntry)
            END AS cntry 
        FROM bronze.erp_loc_a101;
        SET @end_time = GETDATE();
        PRINT '>> Load Duration: ' + CAST(DATEDIFF(SECOND, @start_time, @end_time) AS NVARCHAR) + ' seconds';
        
        -- Loading erp_px_cat_g1v2
        SET @start_time = GETDATE();
        PRINT '>> Truncating Table: silver.erp_px_cat_g1v2';
        TRUNCATE TABLE silver.erp_px_cat_g1v2;
        PRINT '>> Inserting Data Into: silver.erp_px_cat_g1v2';
        INSERT INTO silver.erp_px_cat_g1v2 (id, cat, subcat, maintenance)
        SELECT id, cat, subcat, maintenance FROM bronze.erp_px_cat_g1v2;
        SET @end_time = GETDATE();

        SET @batch_end_time = GETDATE();
        PRINT '=========================================='
        PRINT 'Loading Silver Layer is Completed';
        PRINT '   - Total Load Duration: ' + CAST(DATEDIFF(SECOND, @batch_start_time, @batch_end_time) AS NVARCHAR) + ' seconds';
        PRINT '=========================================='
        
    END TRY
    BEGIN CATCH
        PRINT '=========================================='
        PRINT 'ERROR OCCURED DURING LOADING SILVER LAYER'
        PRINT 'Error Message: ' + ERROR_MESSAGE();
        PRINT 'Error Number: ' + CAST(ERROR_NUMBER() AS NVARCHAR);
        PRINT 'Error State: ' + CAST(ERROR_STATE() AS NVARCHAR);
        PRINT '=========================================='
    END CATCH
END

    - Nulls or duplicates in Primary Keys (Entity Integrity).
    - Unwanted spaces in text fields (Data Cleansing).
    - Invalid chronological ranges (Date Rules).
    - Mathematical Consistency (Sales = Quantity * Price).

*/

HAVING COUNT(*) > 1 OR cst_id IS NULL;

Phase 3: Gold Layer (Dimensional Modeling)

1. Star Schema Creation (Analytical Views)

The final analytical layer was built using Analytical Views. A Star Schema was implemented connecting the fact table with dimensions through dynamic Surrogate Keys, ensuring the Data Warehouse is isolated from changes in the CRM/ERP.

Dimensional Star Schema (Data Mart)

Final Entity-Relationship design implemented in the Gold Layer: fact_sales linked via Foreign Keys to the dim_customers and dim_products dimensions.

ddl_gold.sql (Star Views Generation) 
/*
===============================================================================
DDL Script: Gold Layer Views Creation
===============================================================================
Purpose:
    Constructs the definitive analytical views (Star Schema).
    Transforms and combines cleansed data from the Silver Layer to deliver an 
    enriched dataset ready for business consumption (BI / Reporting).
===============================================================================
*/

-- =============================================================================
-- Dimension: Customers (gold.dim_customers)
-- =============================================================================
IF OBJECT_ID('gold.dim_customers', 'V') IS NOT NULL
    DROP VIEW gold.dim_customers;
GO

CREATE VIEW gold.dim_customers AS
SELECT
    -- Surrogate Key generation (Analytical isolation)
    ROW_NUMBER() OVER (ORDER BY cst_id) AS customer_key, 
    ci.cst_id                          AS customer_id,
    ci.cst_key                         AS customer_number,
    ci.cst_firstname                   AS first_name,
    ci.cst_lastname                    AS last_name,
    la.cntry                           AS country,
    ci.cst_marital_status              AS marital_status,
    -- Master Data Management (MDM): Source priority rule
    CASE 
        WHEN ci.cst_gndr != 'n/a' THEN ci.cst_gndr -- CRM is the primary source
        ELSE COALESCE(ca.gen, 'n/a')               -- ERP acts as fallback
    END                                AS gender,
    ca.bdate                           AS birthdate,
    ci.cst_create_date                 AS create_date
FROM silver.crm_cust_info ci
LEFT JOIN silver.erp_cust_az12 ca
    ON ci.cst_key = ca.cid
LEFT JOIN silver.erp_loc_a101 la
    ON ci.cst_key = la.cid;
GO

-- =============================================================================
-- Dimension: Products (gold.dim_products)
-- =============================================================================
IF OBJECT_ID('gold.dim_products', 'V') IS NOT NULL
    DROP VIEW gold.dim_products;
GO

CREATE VIEW gold.dim_products AS
SELECT
    -- Surrogate Key based on validity start date (SCD)
    ROW_NUMBER() OVER (ORDER BY pn.prd_start_dt, pn.prd_key) AS product_key, 
    pn.prd_id       AS product_id,
    pn.prd_key      AS product_number,
    pn.prd_nm       AS product_name,
    pn.cat_id       AS category_id,
    pc.cat          AS category,
    pc.subcat       AS subcategory,
    pc.maintenance  AS maintenance,
    pn.prd_cost     AS cost,
    pn.prd_line     AS product_line,
    pn.prd_start_dt AS start_date
FROM silver.crm_prd_info pn
LEFT JOIN silver.erp_px_cat_g1v2 pc
    ON pn.cat_id = pc.id
WHERE pn.prd_end_dt IS NULL; -- SCD Type 2 Filter: Only returns active records
GO

-- =============================================================================
-- Fact Table: Sales (gold.fact_sales)
-- =============================================================================
IF OBJECT_ID('gold.fact_sales', 'V') IS NOT NULL
    DROP VIEW gold.fact_sales;
GO

CREATE VIEW gold.fact_sales AS
SELECT
    sd.sls_ord_num  AS order_number,
    pr.product_key  AS product_key,  -- Foreign Key to Products Dimension
    cu.customer_key AS customer_key, -- Foreign Key to Customers Dimension
    sd.sls_order_dt AS order_date,
    sd.sls_ship_dt  AS shipping_date,
    sd.sls_due_dt   AS due_date,
    sd.sls_sales    AS sales_amount,
    sd.sls_quantity AS quantity,
    sd.sls_price    AS price
FROM silver.crm_sales_details sd
LEFT JOIN gold.dim_products pr
    ON sd.sls_prd_key = pr.product_number
LEFT JOIN gold.dim_customers cu
    ON sd.sls_cust_id = cu.customer_id;
GO

2. Quality Assurance Suite (Gold Layer)

As a final step before connecting this Data Warehouse to Business Intelligence tools (Power BI), rigorous Star Schema testing was implemented to prevent data leakage and cartesian products (sales inflation).

quality_checks_gold.sql (Dimensional Model Validation) 
/*
===============================================================================
Quality Checks (QA) - Gold Layer (Star Schema)
===============================================================================
Purpose:
    Validate integrity, consistency, and accuracy of the Gold Layer.
    Ensures the dimensional model is ready for BI tools by verifying:
    - Uniqueness of Surrogate Keys in dimensions.
    - Exact referential integrity between the fact table and dimensions.
===============================================================================
*/

-- ====================================================================
-- Auditing 'gold.dim_customers'
-- ====================================================================
-- Verification of Surrogate Key Uniqueness (Customer Key)
-- Objective: Prevent cartesian products (data duplication) in joins.
-- Expected: 0 Results 
SELECT 
    customer_key,
    COUNT(*) AS duplicate_count
FROM gold.dim_customers
GROUP BY customer_key
HAVING COUNT(*) > 1;

-- ====================================================================
-- Auditing 'gold.dim_products'
-- ====================================================================
-- Verification of Surrogate Key Uniqueness (Product Key)
-- Expected: 0 Results 
SELECT 
    product_key,
    COUNT(*) AS duplicate_count
FROM gold.dim_products
GROUP BY product_key
HAVING COUNT(*) > 1;

-- ====================================================================
-- Auditing 'gold.fact_sales'
-- ====================================================================
-- Verification of Referential Integrity in the Data Model
-- Objective: Detect orphaned records. If a sale has no customer or 
-- product assigned, it will appear as "(Blank)" in Power BI, damaging analytics.
-- Expected: 0 Results
SELECT * 
FROM gold.fact_sales f
LEFT JOIN gold.dim_customers c
    ON c.customer_key = f.customer_key
LEFT JOIN gold.dim_products p
    ON p.product_key = f.product_key
WHERE p.product_key IS NULL 
   OR c.customer_key IS NULL;
