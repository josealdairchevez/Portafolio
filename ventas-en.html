Data Architecture & Modeling

1. Cleansing & Normalization (ETL)

Transitioned from a flat, redundant database to a normalized architecture, ensuring referential integrity and optimizing overall model size.

  • Data transformation and cleansing in Power Query.
  • Primary Key (PK) and Foreign Key (FK) assignment.
  • Elimination of redundant calculated columns.

2. Relational Model (Star Schema)

Efficient analytical design structuring core business information around transactional records using one-to-many (1:*) relationships.

  • Fact Table: `Sales` (Transactional).
  • Dimension Tables (Lookup): `Salespeople`, `Location`, `Products`, `Calendar`, and `Customers`.
  • Single cross-filter direction for optimal query performance.

3. Calculations & DAX Language

Implementation of explicit DAX measures to guarantee dynamic evaluation across segment and dimension filters.

Total Sales = SUM(Ventas[Ventas])

Total Quantity = SUM(Ventas[Cantidad])

Profit Margin = DIVIDE(
  SUM(Ventas[Utilidad]), [Total Sales]
)

Avg. Discount = AVERAGE(Ventas[Descuento])

4. Interactivity & Analytical UX

User-centered design utilizing contextual tooltips and dynamic slicing, enabling deep data discovery without visual overload.

  • Contextual tooltips with secondary metrics (% variance against previous/first tier).
  • Clean navigation to prevent cognitive fatigue for decision-makers.
  • Synchronized slicers for cross-scenario exploration (Category and Year).
