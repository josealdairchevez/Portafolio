DATA ENGINEERING & ANALYTICS

Corporate Data Warehouse:
Medallion Architecture & EDA

End-to-end data pipeline architecture and engineering. From establishing data governance and naming conventions to flat-file ingestion (CRM/ERP), intensive T-SQL data cleansing, dimensional Star Schema modeling, and Exploratory Data Analysis (EDA).

SQL Server T-SQL Data Governance Medallion Architecture Star Schema EDA

Data Governance & Naming Conventions

An enterprise-grade Data Warehouse requires rigorous standardization. Strict Naming Conventions using snake_case were enforced across all logical schemas to guarantee consistency and streamline data lineage traceability between source systems (CRM/ERP) and analytical views.

  • Raw & Cleansed Table Standardization (Bronze & Silver)Entities preserve their source system prefix to ensure full lineage traceability. Pattern: <sourcesystem>_<entity> (e.g., crm_cust_info).
  • Business Domain Modeling (Gold)Final analytical views use business-aligned descriptive names prefixed with dim_ for Dimensions and fact_ for Fact tables.
  • Technical Metadata & AuditingAll system-generated audit columns start with the dwh_ prefix (e.g., dwh_create_date). All surrogate keys enforce the _key suffix.

Architecture Design & ETL Methodology

Combining Kimball dimensional modeling with modern Data Lakehouse patterns, a logical Medallion Architecture was engineered in SQL Server. This design enforces a strict Separation of Concerns (SoC) across raw ingestion, data transformation, and business consumption.

Data Layer Objective & Object Type Applied Transformations Load Strategy
Bronze Layer Traceability. Physical tables (Raw Tables). Data stored strictly "As-Is". None (As-Is). Full Load (Truncate & Bulk Insert).
Silver Layer Cleansing & preparation. Physical tables (Cleaned Tables). Data Cleansing, Normalization, Standardization, and Derived Columns. Full Load (Truncate & Insert).
Gold Layer Business consumption (BI & Analytics). Analytical Views. Data Integration, Aggregations, Business Logic, and Star Schema Modeling. None (Real-time Analytical Views).

Phase 0: Environment Initialization (Setup)

Every resilient Data Warehouse requires a solid foundation. Prior to data ingestion, an idempotent initialization script was engineered to safely recreate the database (forcing active connection rollbacks) and provision the three logical schemas that power the Medallion Architecture.

init_database.sql (Base Environment Setup) 
USE master;
GO

-- Safe database recreation (Idempotency pattern)
IF EXISTS (SELECT 1 FROM sys.databases WHERE name = 'DataWarehouse')
BEGIN
    ALTER DATABASE DataWarehouse SET SINGLE_USER WITH ROLLBACK IMMEDIATE;
    DROP DATABASE DataWarehouse;
END;
GO

CREATE DATABASE DataWarehouse;
GO

USE DataWarehouse;
GO

-- Provisioning logical Medallion Architecture schemas
CREATE SCHEMA bronze;
GO
CREATE SCHEMA silver;
GO
CREATE SCHEMA gold;
GO

Phase 1: Bronze Layer (Data Ingestion)

1. Physical Schema Definition (As-Is DDL)

The primary objective in the Bronze Layer is high-speed, uncorrupted extraction faithful to the original source (As-Is). When modeling the ingestion tables, the raw structure was deliberately preserved to prevent BULK INSERT failures. A key example is the sales table, where CRM dates were intentionally kept as numeric integers (INT), delegating strict type casting to the Silver Layer.

ddl_bronze.sql (Full Raw Layer Definition)

===============================================================================
DDL Script: Bronze Layer Table Creation (Raw Data)
===============================================================================
Purpose:

    principle: Data types strictly match the incoming source CSV files to 
    prevent ingestion failures during Bulk Insert operations.
===============================================================================
*/
